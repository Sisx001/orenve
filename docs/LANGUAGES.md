# Languages & translation

ORYNVE ships in **English** (source of truth) and **Bangla**, and can run in any number of additional languages that you add from the studio. New languages are generated by the AI translation engine, served immediately, and reviewed at your pace.

## Concepts

| Term | Meaning |
|---|---|
| **Built-in language** | `en` and `bn`. Their dictionaries live in `messages/en.json` and `messages/bn.json` and are hand-written. |
| **Registered language** | Any language added under **Settings → Languages & translation**. Its dictionary lives in the database (`Translation` rows) and its content translations live inside the same JSON fields as English and Bangla (`{"en":…,"bn":…,"hi":…}`). |
| **Machine translation** | Text produced by the engine. It is served right away but marked *machine* until someone approves or edits it in the review queue. |
| **Glossary** | Terms that are never translated (brand name, payment brands, channel names). Edit it in the engine settings. |
| **Coverage** | How much of the interface (UI strings) and the content (products, categories, collections, pages, homepage blocks, brand/SEO settings) exists in a language, and how much of that is human-approved. |

## Adding a language

1. **Settings → Languages & translation → Add language.** Pick from the curated list (40 common languages with the right script font and text direction pre-filled) or enter a BCP-47 code such as `hi`, `ar`, `fr`.
2. Choose a **font** for the script (any Google Font family; e.g. *Noto Sans Devanagari* for Hindi, *Noto Naskh Arabic* for Arabic). The storefront loads it only for pages in that language.
3. Click **Generate with AI**. The engine translates the ~420 interface strings in resumable batches (progress bar, safe to close and resume). Requires an AI connection under **Settings → AI concierge**.
4. Click **Translate content** for each content type you want in that language. Each click processes one record so it works on every host, including serverless limits; run it until it reports *done*.
5. Toggle **Enabled**. The language appears in the storefront switcher, gets `hreflang` alternates and sitemap entries, and `<html lang dir>` is set correctly (RTL languages render right-to-left).

Disabled or unknown language paths (`/xx/...`) return a 404, and never stick in the visitor's language cookie.

## Review queue

**Settings → Languages & translation → language → Review.** Two tabs:

- **UI strings** — English source next to the machine text; edit inline, approve, or approve all shown.
- **Content** — one row per translated field (product name, page body…) with the same actions.

Rules the engine follows:

- It never overwrites a **human-approved** translation whose English source has not changed.
- When the English source changes, the translation is regenerated and its approval is reset, because the approval no longer describes the current source.
- It never touches English or Bangla text.
- Glossary terms and placeholders such as `{amount}` or `{items}` are preserved verbatim; markdown and line breaks are kept.

## Studio editing in every language

Every bilingual text field in the studio (`I18nInput`) shows one tab per enabled language. Beside the field, the **AI writer** offers *Write*, *Improve*, *Translate from English* and *All languages*. Saving a form writes every language tab into the same JSON field.

## Engine settings

- **Glossary** — comma-separated terms kept verbatim.
- **Auto-translate new content** — when on, saving a product, page or homepage block queues a translation into every enabled machine language after the response is sent.
- **Machine badge** — shows a small "translated automatically, under review" note in the footer for languages that are still unreviewed.
- **Batch size** — dictionary keys per AI call (default 35; lower it for slow or small models).

## Fallbacks

Any string missing in a language falls back to English. Content fields fall back to English, then to the first available language. The concierge replies in the visitor's language when the model supports it.

## API (studio, permission `i18n.write`, CSRF-protected)

| Endpoint | Purpose |
|---|---|
| `POST /api/admin/i18n/generate` `{ locale, cursor? }` | Translate one dictionary chunk; returns `{ done, nextCursor, translated, total }`. |
| `POST /api/admin/i18n/translate-content` `{ locale, model, cursor? }` | Translate one record of `product|category|collection|page|block|setting`. |
| `GET /api/admin/i18n/coverage?locale=xx` | Coverage counters. |
| `POST /api/admin/i18n/review` | Approve or edit a UI or content translation. |
| `POST /api/admin/i18n/translate-text` `{ text, targetLocale, kind }` | Translate a single string. |

All endpoints return `503 ai.offline` when no AI connection is configured, and are rate-limited per user.

## Notes for developers

- Locale segments are validated by `src/lib/i18n/registry.ts` (built-ins + `Language` table). Middleware only checks the shape (`/^[a-z]{2,3}$/`) so it stays edge-safe.
- `readI18n(fd, name)` in `src/lib/admin/schemas.ts` reads every `${name}_<locale>` field a form submits, so server actions accept new languages without changes.
- Storefront components should use logical CSS (`ps-`/`pe-`, `text-start`) where alignment matters, so RTL languages lay out correctly.
